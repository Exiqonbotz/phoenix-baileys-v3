# Code of Conduct

## Our Standard

Phoenix Baileys V3 aims to maintain a respectful, technical, and constructive open-source environment.

Contributors, maintainers, and users are expected to:

- communicate respectfully
- discuss technical disagreements without personal attacks
- provide useful context when reporting bugs or proposing changes
- respect different experience levels and backgrounds
- avoid harassment, threats, discrimination, or targeted abuse
- avoid publishing private information about other people
- avoid intentionally disrupting project discussions or development

## Technical Discussions

Disagreement about implementation details is normal.

When discussing code, patches, architecture, or upstream behavior:

- focus on the technical issue
- provide evidence when possible
- explain trade-offs clearly
- avoid turning disagreements into personal conflicts
- assume that patches may be changed or rejected if they do not fit the project goals

Phoenix-specific changes should remain small, documented, and reviewable.

The current Phoenix patch policy is documented in:

```text
PHOENIX_PATCHES.md
```

## Issues and Pull Requests

When opening an issue or pull request:

- use a clear title
- describe the problem or change
- include reproduction steps when relevant
- include logs only after removing secrets and personal data
- keep unrelated topics in separate issues
- avoid duplicate reports when an existing issue already covers the same problem

Pull requests may be closed if they are abandoned, unrelated to the project, or conflict with the project direction.

## Security Issues

Do not publish sensitive security vulnerabilities, session credentials, authentication data, private keys, or tokens in public issues.

Security reports should follow:

```text
SECURITY.md
```

## Unacceptable Behavior

The following behavior is not acceptable in project spaces:

- harassment or intimidation
- discriminatory or hateful language
- threats of violence
- sexual harassment
- doxxing or publishing private information
- deliberate spam
- repeated personal attacks
- intentionally misleading security claims
- attempts to pressure maintainers through abuse or threats

## Enforcement

Project maintainers may edit, hide, lock, or remove content that violates this policy.

Depending on severity or repeated behavior, maintainers may also:

- warn a participant
- close an issue or pull request
- restrict participation
- block a user from project spaces

Enforcement decisions should be based on behavior in project spaces rather than technical disagreement or criticism alone.

## Scope

This Code of Conduct applies to:

- the Phoenix Baileys V3 GitHub repository
- project issue discussions
- pull requests
- repository discussions
- other official Phoenix Baileys V3 development spaces

## Project Relationship

Phoenix Baileys V3 is based on Baileys but is maintained independently for the Phoenix ecosystem.

This Code of Conduct applies to Phoenix Baileys V3 project spaces and does not represent the policies of the upstream Baileys maintainers.
